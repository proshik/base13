# BASE 13: room server metrics for Prometheus/Grafana — implementation plan

**Goal:** the room server's own state, every seating, and every player's real pace become
visible in Grafana with alerts, before it stands on a public machine. Today it exposes only
`/health` → `{"ok":true,"rooms":N}` and otherwise talks only through lines of text in
stdout — no technical metrics (connections against their limits, refusals, disconnects,
memory), no product metrics (how many sat down to play, quick game against a room code, how
long people wait for a partner, how long they play together, from which platform and
version), and no lag or performance metrics (network delay to a player, delay added inside
the server, a player's actual tempo, desyncs).

**Architecture:** a second, private HTTP listener renders the server's own state as
Prometheus's text exposition format by hand, behind an optional bearer token, kept strictly
off the public mux. Every counter and histogram is lock-free — atomic increments only — so
the hot path of forwarding a packet does not pay for being measured. The client changes
too: hello now carries `platform` and `version`, and during a network match it sends the
server a short, rate-limited, clamped text report of its own tempo once a window — numbers
the server treats as self-reported, never as ground truth. A dashboard, alert rules and
scrape examples ship in the repository, checked in a test against exactly what the server
renders.

**Tech Stack:** Go 1.26 standard library — the Prometheus text format is written by hand,
the way the WebSocket layer already is, no client library — GDScript (Godot 4.7.2), GUT,
Prometheus, Grafana, Alloy, Docker.

**Change of course, 2026-09-15.** Tasks 1–3 built the exposition by hand, as written
above, on the assumption that the server must stay free of dependencies. That was a
description of how the server had been built, not a rule, and the owner allowed
dependencies once asked. The hand-written text format, histograms and `/proc` parsing
were then replaced with `prometheus/client_golang`: the event families keep their names,
labels and buckets, while the runtime and process figures became the library's standard
`go_*` and `process_*` ones, and `server/process.go` is gone. What the tasks below say about
lock-free hand-written histograms, a render mutex, and `relay_sched_latency_seconds` and the
other runtime names is history; "What came out" at the end describes the server as it is.

**Owner decisions:**
- Prometheus / Alloy live **on the same machine** — metrics never reach the internet.
- "Users" are **events only**: no IP, no identifiers, no room codes, no seeds. The server
  does not count unique people — deliberate, and the README says so.
- **The client changes**: hello gains `platform` and `version`; during a network match the
  client sends the server a pace report once a window (added at the owner's request: "lag
  and performance metrics").
- The repository gets a **dashboard, alerts and scrape examples**.

**Gates:** nothing, in either direction. This plan does not gate the deployment: the
machine can go up before it lands, and metrics arrive afterward, shipped as `0.5.0`.

## Security model

Required in full by every task below, not only the ones that touch the network — a metrics
endpoint is, by construction, a new way to reach the process from outside.

1. **A listener of its own.** `METRICS_ADDR` / `-metrics-addr`, empty means off (the
   default). `/metrics` never appears on the public mux (`routes`) — the proxy in front,
   per the README, forwards every path, and a test stands guard over that.
2. **A matching port is a refusal to start.** Ports are compared after `normalizeAddr` +
   `net.SplitHostPort`, not as strings: on macOS `127.0.0.1:27014` sits right next to
   `:27014`, and a proxy on loopback would land on the metrics port.
3. **A token — optional, from the environment only** (`METRICS_TOKEN`, no flag — flags are
   visible in `ps`). Compared with `subtle.ConstantTimeCompare` over the sha256 of both
   strings, so length does not leak. Under 16 bytes refuses to start. 401 plus
   `WWW-Authenticate: Bearer`. Needed because `-p 127.0.0.1:…` only restricts the host — a
   neighboring container on the docker bridge reaches straight through.
4. **Its own `http.Server`**, not `DefaultServeMux`: `ReadHeaderTimeout` 5s, read/write
   10s, idle 60s, `MaxHeaderBytes` 8KB. Only `GET /metrics` (405 with `Allow`, everything
   else 404). Served through `promhttp`, at most 4 scrapes in flight and a 5s timeout, once
   the metrics moved to `client_golang` (see the change of course above) — the render mutex
   this point originally described is gone with the hand-written exposition. No pprof.
5. **Cardinality is closed by the server.** Labels come only from closed sets; `game` (the
   client's own string) never appears. platform: `web|web_android|web_ios|macos|windows|linux|android|ios`, no field → `unknown`, anything else → `other`. version:
   `^\d{1,3}\.\d{1,3}\.\d{1,3}$`, none → `unknown`, anything else → `other`. Versions are
   not accumulated in a table — 32 fakes could poison it — they are counted at scrape time
   over the live membership, top 10 plus `other`.
6. **Privacy under test.** A render taken after seating in a room with a known code and
   seed carries neither — the format checker only lets label values through
   `[a-z0-9_.]` (room codes are uppercase, so they cannot pass).
7. **The client's own numbers are not taken on faith.** A pace report is a text frame
   ≤512 bytes (the existing cap), parsed into a fixed structure, every field clamped to a
   range, no more than once per 4 seconds per connection (extras are dropped and counted),
   never logged, never relayed to the partner, and never written verbatim anywhere. A
   desync is counted once per room. A forged report can skew the distribution — that is a
   known limit, and the README names it.
8. **RTT cannot be forged.** A ping carries 8 bytes — the moment it was sent; a pong is
   accepted only if its payload equals the connection's own last-sent ping, and only once
   (a CAS to zero). Unsolicited pongs are ignored.
9. **The image:** no `EXPOSE` for the metrics port (`docker run -P` would publish it on
   every interface). A binary run without Docker on a non-loopback address and no token
   prints a warning.
10. **`release.yml`:** `${{ inputs.version }}` is currently interpolated straight into
    `run:` (lines 57–58, 145, 165–168). The first step checks the format through `env:`,
    and the affected steps move to `env:` too — closing, in passing, a deferred item from
    the hardening plan.

## Global Constraints

- TDD: a failing test first, then the minimal code, then it passes, then a commit
  (`feat:`/`fix:`/`chore:`/`docs:`).
- `./tools/check_server_neutral.sh` stays clean: the prefix is `relay_`, and `server/*.go`
  carries none of the words `level` (including "top-level", "log level"), `tank(s)`,
  `base13` — comments included.
- Every test builds `&server{hub: NewHub()}` as a literal, and `newRoom(...)` bare — new
  state works from the zero value: `stats` by value in `Hub`, typed `atomic.Uint64`,
  `Room` and `Member` hold a `*stats` pointer (set in `Hub.create` / `JoinAs`), every
  method is nil-safe.
- **Histograms without locks**: non-cumulative buckets are `atomic.Uint64`, the sum is
  atomic nanoseconds or units; `_count` at render time is the sum of the buckets (always
  equal to `+Inf`). The hot path (forwarding a packet) pays only atomic increments.
- Durations a test shortens are fields on `server`, never package variables.
- Lock order: `hub.mu → room.mu`; metrics take no mutex on the event path. A scrape copies
  room pointers and `hub.limit` under `hub.mu`, releases it, then locks each room
  separately.
- Tasks 5–10 and 12: additionally run `cd server && go test -race ./...`.

## Metric set

All names carry the `relay_` prefix, and every label combination is exposed from zero
rather than only after it is first seen — roughly 450 series in total.

| Group | Metrics |
|---|---|
| Build, process | `build_info{version,goversion}`, `start_time_seconds`, `process_cpu_seconds_total`, `process_resident_memory_bytes`, `process_open_fds` (only where `/proc` exists), `goroutines`, `heap_live_bytes`, `runtime_memory_bytes`, `gc_cycles_total` |
| Right now (at scrape) | `connections`, `connections_limit`, `rooms{kind=code\|quick,state=waiting\|playing\|interrupted\|empty}`, `rooms_limit`, `players{platform}`, `players_by_version{version}`, `journal_bytes` |
| Connections | `connections_opened_total`, `refusals_total{reason=rooms_limit\|connections_limit\|full\|no_room\|bad_hello\|other}` (on the wire both limits still say `busy`), `disconnects_total{cause=goodbye\|idle\|lost\|cut\|protocol}` |
| Product | `seatings_total{action=create\|join\|quick\|return,platform}`, `rooms_created_total{kind}`, `pairings_total{kind}` (both seats filled for the first time — a return does not count), `pairing_wait_seconds{kind,outcome=paired\|abandoned}`, `played_seconds{kind}` (time together only; `_sum` over a day = pair-hours), `journal_capped_total` |
| **Lag: network** | `rtt_seconds{platform}` (the server's own ping/pong, once per 20s per connection; buckets 0.01/0.025/0.05/0.1/0.2/0.4/0.8/1.6), `packet_gap_worst_seconds` (the worst gap in the incoming stream over a window — jitter; 0.05/0.1/0.25/0.5/1/2.5) |
| **Lag: server** | `forward_seconds` (from reading a packet to writing it into the partner's socket — the server's own contribution plus a slow socket; 0.0005/0.001/0.005/0.01/0.05/0.1/0.5/1), `sched_latency_seconds` and `gc_pause_seconds` (from `runtime/metrics`, rebucketed; the process is starved of CPU), `members_evicted_total`, `packets_total`, `packet_bytes_total` |
| **Lag: at the player** (client reports) | `client_speed_ratio{platform}` (share of 60 ticks/s over a window; 0.5/0.75/0.9/0.95/0.99/1.01), `client_windows_total{platform,verdict=smooth\|network\|machine}` (≥95% is smooth; otherwise waits happened → network, none happened → machine — the rule from CLAUDE.md), `client_input_delay_ticks` (3/4/6/8/10/12/16), `client_waits_total`, `client_fps{platform}` (15/30/45/55/60/120), `desynced_matches_total{kind}` (once per room), `client_reports_rejected_total{why=early\|malformed}` |
| Web | `http_responses_total{route=page\|wasm\|other,class=2xx..5xx,encoding=gzip\|identity}`, `http_response_seconds{route}` (for wasm, how long a player waits for the engine to load; 0.1/0.5/1/2.5/5/10/30/60) |

Notes that go into the panel descriptions: `played_seconds` and `abandoned` are observed in
`Sweep` with a 5–6 minute lag, and rooms still alive at restart are never observed; `return`
is a `join` with `since > 0`; `packet_gap` mixes real stutter with pauses (the STATS
screen, a hidden tab); client reports exist only in a network match through the server —
single-player and LAN are invisible; client numbers are self-reported.

## Not in this plan

- Single-player and LAN performance: neither has a connection to the server, so neither
  has a report channel.
- Engine start time in the browser (load to first frame) — that needs JS on the page.
- **A defect found along the way:** a quick-game waiter who drops briefly and returns by
  `join` with the code; if in that gap someone else pressed Quick, the room was removed
  from `waiting` and is not added back. `pairing_wait_seconds{outcome=abandoned}` will show
  it; fixed separately.
- Cleaning up the version in the macOS preset, pprof, unique visitors.

## What came out, 2026-09-15

Every task above is done, on `feat/metrics`; it ships in the next image.

**The server runs on `client_golang` v1.24.1**, not on a hand-written exposition (see the
change of course at the top). The standard collectors replaced the plan's own runtime and
process families: `go_sched_latencies_seconds` for CPU starvation, `go_gc_pauses_seconds`,
`go_goroutines`, `go_gc_heap_live_bytes`, `process_start_time_seconds`,
`process_resident_memory_bytes`, `process_open_fds`. The input delay buckets became 5, 6, 8,
10, 12, 14, 16, because the network lag plan moved the client's delay to 5..16. A client
sends one pace report per 300-tick `[net]` report; the server takes a burst of two and earns
one back every four seconds, and counts a desync once a room, only in a room that paired.
The metrics listener serves `/metrics` through `promhttp`, capped at 4 scrapes in flight with
a 5s timeout, in place of the render-into-a-buffer mutex the security model originally
called for.

**Load, `BASE13_LOAD=1 go test -run TestLoadManyPairs`.** Delivery stayed at 100.2% of sent
with nothing late at 10, 50 and 200 pairs through every task that touched the packet path.
The heap at 200 pairs read +9.3 MB before Task 8 and +10.0 to +10.3 MB after it (the 8-byte
stamp on a queued packet, down from +11.4 with a `time.Time`); across the move to
`client_golang` it read 9.6–9.9 MB before and 10.6–11.2 MB after, and a 200-pair run on its
own gave +11.5 MB for both, so the difference is run order and the collector, not a cost per
connection.

**A scrape** of a server that had seen pairs, reports, refusals and downloads: 733 samples in
104 families, 575 of them `relay_`, 151 `go_` and 7 `process_` on macOS; the Linux image adds
the two `process_network_*` counters. About 64 KB of text, 10 KB gzipped. The plan estimated
about 450 series of the server's own.

**The operator's side** is in `deploy/`: the Prometheus scrape job, a Grafana Alloy example,
thirteen alert rules and a dashboard of thirty-five panels in five rows. `server/deploy_test.go`
checks every `relay_`, `go_` and `process_` name those files use against a real scrape, and
that every panel reads through the datasource variable. Checked by hand as well: `promtool
check rules`, `check config` and `check metrics`, `alloy validate`, and the dashboard imported
into Grafana 13 against a Prometheus scraping a live server, with every panel's queries
returning data. One thing found on the way: `go test` does not notice a change outside the
module, so a result cached before a dashboard edit would pass after it; `tools/test.sh` now
runs the Go tests with `-count=1`.

**Deferred:**

- The release pushes `:version` and `:latest` before the check that the published image
  answers.
- The gzipped engine goes out without `Content-Length`: chunked, without sendfile, and with
  no download size for the loader's progress.
- The macOS export preset hardcodes `application/version` 0.1.0, so `Info.plist` does not
  follow the stamped version.
- A quick-game waiter who briefly drops and returns by code is no longer findable by
  matchmaking.
- `${{ github.ref }}` and `${{ inputs.target }}` are still interpolated into `run:` in
  `release.yml`.
- The per-process ping offset hides the uptime, but a client can still notice a restart by
  comparing two connections.
- The metrics listener has no cap on connections of its own.
- Single-player and LAN games are not measured: neither talks to the server.
- The engine's start time in the browser, from page load to the first frame, needs JS on the
  page.
